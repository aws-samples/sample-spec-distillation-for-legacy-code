# Modernization assessment (raw-code)

- Business rule: An invoice must have a non-empty vendor code. (InvoiceService.vb:L13-L13)
- Business rule: An invoice must have a non-empty invoice number. (InvoiceService.vb:L14-L14)
- Business rule: An invoice must have at least one line item. (InvoiceService.vb:L15-L15)
- [ISSUE: inconsistency] Business rule: An invoice may not exceed MAX_LINES (25) line items. The comment on line 7 says 'Max 10 lines per invoice' but the constant is set to 25 — these are inconsistent. (InvoiceService.vb:L7-L8)
- [ISSUE: inconsistency] Business rule: The tax rate applied to each line when computing the invoice total in SubmitInvoice is 8% (multiplier 1.08). However, RecalculateTotal uses a 7% tax rate (multiplier 1.07). These two methods produce different totals for the same lines — the rewrite team must decide which rate is correct. (InvoiceService.vb:L20-L20; InvoiceService.vb:L35-L35)
- [ISSUE: inconsistency] Business rule: RecalculateTotal uses MidpointRounding.AwayFromZero explicitly, while SubmitInvoice uses Math.Round with default (banker's) rounding. This means the two totals can differ even if the tax rate were the same. (InvoiceService.vb:L20-L20; InvoiceService.vb:L35-L35)
- Business rule: The invoice total (as computed in SubmitInvoice) must not exceed MAX_AMOUNT (100,000). The rewrite must clarify whether this cap applies to the pre-tax or post-tax total, and which tax rate is authoritative. (InvoiceService.vb:L22-L22)
- [ISSUE: undocumented_feature] Business rule: Invoices from vendors whose code starts with 'ZZ' are automatically set to APPROVED status; all others are set to PENDING_APPROVAL. This special-vendor rule is undocumented — no comment explains the business meaning of the 'ZZ' prefix. (InvoiceService.vb:L24-L27)
- [ISSUE: undocumented_feature] Business rule (in database): The stored procedure overrides APPROVED status back to PENDING_APPROVAL when the total exceeds 50,000. This rule exists only in the database and is invisible to the VB application layer — the application may return 'APPROVED' to the caller while the database silently stores 'PENDING_APPROVAL', creating a discrepancy between the returned value and the persisted value. (schema.sql:L20-L21; InvoiceService.vb:L28-L29)
- [ISSUE: logic_flaw] Logic flaw: The application-level MAX_AMOUNT cap is 100,000, but the database silently demotes APPROVED invoices above 50,000 to PENDING_APPROVAL. The two thresholds are inconsistent and the application is unaware of the database override, so the return value of SubmitInvoice can be wrong for ZZ-vendor invoices between 50,001 and 100,000. (InvoiceService.vb:L9-L9; InvoiceService.vb:L22-L22; schema.sql:L20-L21)
- [ISSUE: logic_flaw] Business rule: The database enforces a unique constraint on (VendorCode, InvoiceNo). The application does not check for duplicates before calling SaveInvoice, so duplicate submissions will throw an unhandled SQL exception rather than returning a structured error code. (schema.sql:L11-L11; InvoiceService.vb:L48-L59)
- [ISSUE: logic_flaw] Business rule: The database enforces CHECK (Total > 0) on the Invoice table. The application does not validate that the computed total is positive before calling SaveInvoice, so a zero or negative total (e.g. from zero-quantity lines) will throw an unhandled SQL exception. (schema.sql:L8-L8; InvoiceService.vb:L18-L22)
- Business rule: IsOverdue returns true only when the overdue period is strictly greater than 30 days (i.e. 31+ days). A 30-day-old invoice is not considered overdue. The rewrite team must confirm whether the boundary is inclusive or exclusive. (InvoiceService.vb:L40-L42)
- [ISSUE: dead_code] Dead code: LegacyDiscount is a private method that is never called anywhere in the class. The rewrite team must determine whether this 2% discount rule was intentionally retired or was accidentally omitted from the active code path. (InvoiceService.vb:L44-L46)
- [ISSUE: duplicated_logic] Duplicated logic: Total calculation logic is duplicated between SubmitInvoice (lines 18-21) and RecalculateTotal (lines 32-38), with different tax rates and different rounding modes. There is no single authoritative total-calculation function. (InvoiceService.vb:L18-L21; InvoiceService.vb:L32-L38)
- [ISSUE: undocumented_feature] Undocumented feature: The VendorCode column in the database is VARCHAR(10), but there is no length validation in the application. A vendorCode longer than 10 characters will cause a SQL truncation error or exception at runtime. (schema.sql:L6-L6; InvoiceService.vb:L13-L13)
- [ISSUE: undocumented_feature] Undocumented feature: The InvoiceNo column in the database is VARCHAR(20), but there is no length validation in the application. An invoiceNo longer than 20 characters will cause a SQL truncation error or exception at runtime. (schema.sql:L7-L7; InvoiceService.vb:L14-L14)
